# 定位脚手架（Locator Scaffold）— 可复用

## 1. 定位串格式

`locator` 优先用「§章节 + para 序号」或「可检索原文锚点」，两者至少给一个：

| 稿件形态 | 推荐 locator 形态 | 示例 |
|---|---|---|
| 有章节号的稿件 | `§3.2 para4` | `§3.2 para4` |
| 摘要/引言等无编号段 | `摘要 para2` / `引言 para1` | `摘要 para2` |
| 表格 | `表2 第3行` | `表2 第3行` |
| 图 | `图3 图注` | `图3 图注` |
| 无结构纯文本 | `锚点:<原句前12字>` | `锚点:本研究共招募 50 名` |
| 附录/补充材料 | `附录B para2` | `附录B para2` |

硬规则：
1. `locator` **不得为空**（机检项 `locator_present`）。
2. `revision_log.original` 必须是基线稿中**可检索的原句**（归一化后子串匹配）。
3. `revision_log.revised` 必须是修订稿中**可检索的新句**（归一化后子串匹配）。
4. 定位在改稿后仍应有效：优先用章节+段落号而非行号（行号会随改稿漂移）。

## 2. 定位脚手架五步（写台账时逐条执行）

1. **抄**：从基线稿复制出问题句 → `revision_log.original`（不要转述、不要改标点）。
2. **定位**：给该句一个 `locator`（§/段/表/锚点）。
3. **改**：写出改后句 → `revision_log.revised`（与修订稿最终文字**逐字一致**）。
4. **据**：写 `revision_log.basis`（依据来源，如 `M03 表2 样本量数据`）+ `reason`（回应哪个 sid）。
5. **证**：写 `evidence`（补什么、状态、出处），引文须能在基线稿中逐字回证。

## 3. 联动改动检查表

改一处常牵动别处，逐项核对并**各建一条台账行**：

- [ ] 摘要中的数字/结论 ↔ 正文
- [ ] 正文表格 ↔ 图表编号与正文引用（"见图 3" ↔ 图号重编号）
- [ ] 章节号/交叉引用（"如 3.2 节所述"）
- [ ] 参考文献列表 ↔ 正文引用（新增/删除文献后编号重排）
- [ ] 方法节 ↔ 附录中的实现细节
- [ ] 结论节 ↔ 结果节的数字一致性
- [ ] 摘要/结论 ↔ 局限说明（补充证据后结论措辞是否需同步）

## 4. 不可定位时的处置

意见指向的内容在基线稿中找不到（版本不匹配 / 稿件缺章节）：

1. 台账行标 `unresolvable: true`；
2. **不要乱改**基线稿；
3. 回复信如实写：`<意见>指向的内容在指定基线稿中未找到（可能指向旧版本或其他章节），我们已核对全部材料，无法定位；请编辑确认具体位置，我们将在收到指正后补充。`
4. 记入 `version_boundary.material_gaps`，并在 result.json 的 `uncertainty` 中列明。

## 5. 定位有效性自查（交付前跑一次）

```bash
python3 scripts/ledger_audit.py --ledger <台账> --letter <回复信> --revised <修订稿> \
  --original <基线稿提取目录> --out <审计报告>
```

- `revised_in_revised` / `original_in_baseline` 全 match → 定位在两稿中均有效。
- `unbacked` 非空 → 有引文在基线稿中查不到，须改出处或降级为替代说明。
- `gates.original.state != "enforced"` → 基线稿未提供，**未核对 ≠ 通过**，回复信不得宣称已核对。
