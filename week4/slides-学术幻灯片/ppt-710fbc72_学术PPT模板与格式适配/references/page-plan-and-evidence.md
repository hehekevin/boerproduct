# 主线提取与页计划方法（paper2deck 配套参考）

## 1. 论文主线提取四步法

论文是连续叙述，PPT 是页级离散主张。转换的目标函数是：**评委看完每页都能复述出该页主张，且该主张挂着论文里的某个证据**。

1. **问题定位**：论文要解决什么？为什么现有方法不行（gap statement 通常在 Introduction 第 2-3 段）？
   - 页面表达：一句话问题 + 一句话 gap。问题页只放这两句，不放文献综述。
2. **方法骨架**：核心做法是几个组件？数据怎么流过？
   - 页面表达：每个组件一条要点；组件间用箭头/序号表达流向。方法细节超过 3 页时合并同类项，保留"听众能复述机制"的最小集。
3. **证据分组**：论文的关键结果有几组？每组挂在哪张图/表？
   - **一组结果一页**。表格页只保留 2-3 个关键列，其余列删掉并注明"完整表见论文 Table x"；数字逐字搬运，不取整、不换算单位。
4. **限制与边界**：作者自己承认什么（§Limitations）？哪些结论证据强度弱（单数据集/小样本/无消融）？
   - 限制页**必须存在**——这是学术汇报可信度来源；把"结论强度"标出来（强=多数据集+消融支撑；弱=单实验）。

## 2. 页序规则（不是论文目录顺序）

- 标题页 → 问题页 → 方法页 → 结果页（按重要性排，**最重要的结果放最前**）→ 限制页 → 结论页。
- 结论页数字必须与结果页一致（同一来源 quote），不允许结论页出现未在结果页出现过的数字。
- 若案例指定页数上限 N：标题+问题 2 页、方法 ceil((N-5)/3) 页、结果 N-方法-4 页、限制 1 页、结论 1 页为基准分配。

## 3. 页级证据映射规范

`evidence_map.jsonl` 每行字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| slide_no | 是 | 页码（从1起） |
| claim | 是 | 该页主张（与 page_plan 一致） |
| type | 是 | figure / table / section / quote；数值事实必须是 quote |
| locator | 是 | Fig.n p.x / Table n / §x.y / PAGE n 锚点 |
| quote | 数值类必填 | 逐字原文；空白差异可容忍，改写不可 |
| figure_mode | 图片降级时填 | page_render / ocr |

**红线**：
- 页面出现论文没有的数字 → 直接删除该数字（不是补 quote）。
- 两个来源冲突（正文 vs 表格数字不一致）→ 采用表格数值并标注 uncertainty。
- 引用张冠李戴（把 Fig.3 的数据说成 Fig.2）→ evidence_check 无法发现语义错误，靠自己按 locator 回查图片文件核对，发现后立即纠正。

## 4. 图表引用一致性检查（生成前手工核对，生成后 verify 脚本兜底）

1. 页面文字提到"图 N / Table N"→ deck.json 对应页 figure.caption 必须以"图 N"或"Table N"开头，且 source_locator 与 evidence_map.locator 一致。
2. 结果页上没有图的（只有表格）→ layout=table，不许放无关示意图凑数。
3. 讲解顺序与图出现顺序一致：先讲图再讲数据，页面 bullets 第一条必须指向该图的观察结论。
