# 意见分类法（Comment Taxonomy）— 可直接复用

返修台账的第一列 `type` 与 `severity` 取自本表。本表是**空模板 + 判定规则**，不含任何正式案例答案。

## 一、意见类型（type）

| type | 中文 | 判定信号（命中任一即归此类） | 必须产出的动作 |
|---|---|---|---|
| `方法` | 方法学 | 抽样/设计/统计方法/模型设定/参数选择/对照是否充分 | 改稿段落 + 方法说明；必要时补分析 |
| `数据` | 数据与结果 | 样本量/数据来源/数值不一致/图表与正文对不上/缺失实验 | 改稿数值 + 逐字可回证的数据出处 |
| `写作` | 表述与论证 | 逻辑不清/表述含糊/论证跳跃/术语不统一/摘要与正文不符 | 改写句 + 前后呼应处理 |
| `格式` | 格式与引用 | 图表编号/参考文献格式/行距/标题层级/单位与缩写 | 批量格式处理 + 一条汇总回复（列明细） |
| `伦理` | 伦理与合规 | 知情同意/伦理审批号/数据可获取性/利益冲突/作者贡献 | 合规声明或局限说明；无审批号则标 needs_author |
| `定位` | 稿件定位问题 | 意见指向的内容在基线稿中找不到 | 记 unresolvable，如实说明"基线稿无此内容" |

> 复合意见按**主类型**归类，副要求仍各自拆成子要求（sub）。

## 二、严重程度（severity）

| severity | 判定规则 | 处置约束 |
|---|---|---|
| `major` | 影响结论有效性、样本/统计、伦理合规，或审稿人明确要求补做实验/数据 | 必须给明确决策 + 实质修改落地；不可只写"已讨论" |
| `minor` | 表述、格式、局部表述精确度 | 可批量处理；允许 partially_adopted + 说明 |

## 三、子要求拆解规则（拆净）

一条意见内含**多个可独立验证的动作**时，必须拆成多个子要求 `sid`（如 `C01a`/`C01b`/`C01c`）。

必拆信号：
- 出现并列动词（"补实验**并**更新图3"）
- 出现"同时/另外/以及"连接的两个不同动作
- 同一句里同时指向两个不同位置（摘要与正文）
- 一处要求补数据，另一处要求补文献讨论

不拆信号：同一动作的重复表述、纯格式批量项（可归一条 + 明细表）。

## 四、决策（decision）与语气（tone）映射

| 决策 | 何时用 | 必填 | 建议语气 |
|---|---|---|---|
| `adopted` | 材料支持且能落地 | revision_log 四字段 | `accept` |
| `partially_adopted` | 只能做一部分（缺材料/超范围） | decision_rationale ≥10 字 + 替代方案 | `clarify` |
| `rejected` | 意见本身有误或与稿件冲突 | decision_rationale ≥10 字 + 依据 | `polite_pushback` / `appeal` |

语气四档：`accept`（致谢+已改）、`clarify`（澄清误解，引原文）、`polite_pushback`（先认可再给理由）、`appeal`（仅用于明显误判）。禁用词见 `scripts/ledger_audit.py` 的 `BAD_TONE` / `OVERPROMISE`。

## 五、交叉意见

两条意见指向同一问题时（如 R1-3 与 R2-1 同问样本量），在 `relates_to` 互相登记，并在两处用**同一口径**回复，避免自相矛盾。

## 六、可复用字段字典

`comments.jsonl` 一行（Stage 1 产出）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `cm` | string | 是 | 意见编号（C01） |
| `reviewer` | string | 是 | 审稿人（R1/R2） |
| `type` | enum | 是 | 见上表 |
| `severity` | enum | 是 | major / minor |
| `raw_quote` | string | 是 | 意见逐字摘录（用于回溯，不改写） |
| `subs[].sid` | string | 是 | 子要求编号（C01a） |
| `subs[].requirement` | string | 是 | 子要求复述 |
| `subs[].action_needed` | string | 是 | 可执行动作描述 |
| `relates_to` | string[] | 否 | 交叉意见编号 |

`response_ledger.jsonl` 一行（Stage 2 产出）见 `templates/ledger_template.jsonl`。
