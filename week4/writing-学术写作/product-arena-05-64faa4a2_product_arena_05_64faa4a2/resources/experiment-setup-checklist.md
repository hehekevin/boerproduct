# 实验设置要素清单

使用说明：Phase 1 抽取要素与 Phase 2 缺口分析时逐项核对。每项须标注来源（来源编号 S#），材料未提供的标 `[TODO]`，不得凭常识填默认值。

## 一、数据集要素

| 序号 | 要素 | 要求 |
|---|---|---|
| D1 | 数据集名称与版本 | 版本号、发布年份或引用 |
| D2 | 来源与获取方式 | 下载地址、申请流程或附件 |
| D3 | 规模 | 样本数、类别数、字段数、平均长度等 |
| D4 | 预处理步骤 | 每步操作及参数（阈值、归一化方式、分词器等） |
| D5 | 划分比例 | 训练/验证/测试比例或固定划分文件 |
| D6 | 随机方式 | 划分所用种子或分层策略 |
| D7 | 子集用途 | 各子集用于训练、调参还是最终报告 |

## 二、训练要素

| 序号 | 要素 | 要求 |
|---|---|---|
| T1 | 模型结构与规模 | 层数、宽度、参数量 |
| T2 | 初始化方式 | 预训练权重及来源，或随机初始化方案 |
| T3 | 优化器 | 名称及超参（动量、beta、权重衰减等） |
| T4 | 学习率 | 初始值、调度策略、预热设置 |
| T5 | batch size 与 epoch 数 | 数值及作用对象 |
| T6 | 正则化 | dropout 比例、权重衰减、数据增广 |
| T7 | 早停与模型选择 | 判据、耐心值、选择哪个 checkpoint |

## 三、硬件与软件要素

| 序号 | 要素 | 要求 |
|---|---|---|
| H1 | 硬件 | GPU 型号与数量、CPU、内存 |
| H2 | 操作系统与驱动 | 版本号 |
| H3 | 框架与版本 | 深度学习框架、关键依赖库及版本 |
| H4 | CUDA 或运行时版本 | 数值 |
| H5 | 环境复现方式 | environment 文件、requirements、容器镜像 |
| H6 | 运行耗时与资源占用 | 材料有则写，无则不写 |

## 四、评测要素

| 序号 | 要素 | 要求 |
|---|---|---|
| E1 | 指标清单 | 每个指标的计算定义与平均方式 |
| E2 | 指标实现来源 | 官方工具包、库及版本，或自定义实现 |
| E3 | 评测协议 | 用哪个子集、是否多次运行、如何汇总 |
| E4 | 统计检验 | 检验类型、显著性水平、多重比较处理 |
| E5 | 重复次数与随机种子 | 运行次数、种子列表或种子策略 |
| E6 | 报告形式 | 均值加减标准差、最优值或其他 |

## 五、对照要素

| 序号 | 要素 | 要求 |
|---|---|---|
| C1 | 基线清单 | 每个基线名称、出处 |
| C2 | 基线版本与实现 | 官方实现或自实现，代码版本 |
| C3 | 同预算条件 | 数据、参数量、算力、调参预算是否对齐 |
| C4 | 消融设置 | 消融哪些组件、固定哪些条件 |
| C5 | 复现差异 | 与基线原报告设置的差异及理由 |

## 使用规则

1. 每项要素只能取值于材料或作者确认，两者皆无时标 TODO。
2. 同一要素多处取值冲突时，按 配置文件与日志 > 结果表 > 实验记录文字 > 论文旧稿 优先级裁决，并记入冲突清单。
3. 本清单同时用作成稿 Phase 4 的要素覆盖检查依据：六类要素中步骤、设置、参数、数据集、对照、复现与限制，凡本清单缺项且成稿未标 TODO 的，视为覆盖不足。
