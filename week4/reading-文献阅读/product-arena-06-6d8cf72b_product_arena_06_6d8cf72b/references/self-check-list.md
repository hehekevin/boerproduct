# 自检清单（可独立执行）

运行结束前逐项检查。每项通过打勾，不通过就地修正后重新检查。可将本清单复制到 work 目录作为检查记录。

## 一、契约与完整性

1. [ ] result.json 存在于 /app/output/，JSON 语法可解析。
2. [ ] result.json 含 case_id，与 case.json 一致。
3. [ ] result.json 含 output_contract 声明的全部字段，无缺键。
4. [ ] 笔记文件位于 /app/output/notes/，文件名含 case_id。
5. [ ] 单文件不超过 500KB。

## 二、字段覆盖

6. [ ] 研究问题、数据、方法条件、主要发现、局限、结论六类字段均已填写。
7. [ ] 任一空白字段都在"未报告清单"中显式列出，无静默留空。
8. [ ] 局限字段只含论文原文明说的局限，推测性隐患在评价栏。

## 三、锚点与可核验性

9. [ ] 每条事实栏条目都以锚点开头，锚点格式符合 evidence-anchor-spec.md（至少含页码与章节）。
10. [ ] 抽查 3 个锚点回原文核对：位置真实对应，结论与原文一致。
11. [ ] 无"见原文""见第2节"等笼统出处。

## 四、数字正确性

12. [ ] 所有数字与原文逐字一致，无四舍五入、无凭印象补数。
13. [ ] 摘要与结论中的关键数字已与正文表格比对，核对结果写入"数字核对记录"。
14. [ ] 图表数字不可读处标注 [图表数字不可读]，无估算值。
15. [ ] 数字冲突保留两个值与各自锚点，未擅自裁断。

## 五、事实与评价分离

16. [ ] 事实栏与评价栏分栏，评价未混入事实栏。
17. [ ] 事实栏无第一人称判断语句（如"我认为"）。

## 六、诚实性

18. [ ] 未报告、无法判断、材料冲突三类清单已显式列出（可为空但须写"无"）。
19. [ ] status 与实际完成度一致：有缺口标"部分完成"，写明缺口与人工接管位置。
20. [ ] 未伪造任何数据、文献状态或运行结果。

## 七、产物落盘

21. [ ] /app/work/ 留有 plan.md、skeleton.md、excerpts.md 供过程复核。
22. [ ] change_log 记录了关键变更。
