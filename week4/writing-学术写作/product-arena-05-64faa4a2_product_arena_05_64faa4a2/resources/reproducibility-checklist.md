# 可复现性核查清单

使用说明：成稿 Phase 3 与 Phase 4 时逐项核查。目标：读者不联系作者即可复做实验。每项标注状态：具备（来源 S#）、缺失（TODO）。

## 复现十项

| 序号 | 核查项 | 达标标准 | 状态 |
|---|---|---|---|
| R1 | 代码获取 | 仓库地址加提交号，或随文附件说明 | 具备 / TODO |
| R2 | 环境说明 | environment 文件、requirements 或容器镜像引用 | 具备 / TODO |
| R3 | 依赖版本 | 框架与关键库的具体版本号 | 具备 / TODO |
| R4 | 数据获取 | 数据集版本、下载或申请方式 | 具备 / TODO |
| R5 | 数据处理 | 预处理脚本或步骤参数可照做 | 具备 / TODO |
| R6 | 划分复现 | 划分种子或固定划分文件 | 具备 / TODO |
| R7 | 随机种子 | 种子列表或种子策略写明 | 具备 / TODO |
| R8 | 运行命令 | 训练与评测各给出一条可执行命令 | 具备 / TODO |
| R9 | 硬件条件 | GPU 型号与数量，显存需求 | 具备 / TODO |
| R10 | 预期结果 | 参考结果（表或数值）与运行耗时，便于核对 | 具备 / TODO |

## 使用规则

1. R1 至 R10 在成稿的 Reproducibility 小节中逐项体现；无法提供的项写 `[TODO: 缺少 R# 的内容]`，不省略条目。
2. 某项材料中完全无据时，不得用通用描述（如 环境为常见深度学习环境）充数。
3. 汇总统计：成稿交付时统计 具备 x 项 / TODO y 项，写入 fact_source_map 与 result.json 的 gaps 汇总，作为复现完整度的量化指标。
