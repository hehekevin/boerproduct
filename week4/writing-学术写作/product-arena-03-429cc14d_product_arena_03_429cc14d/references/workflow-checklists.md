# 工作流核查清单与异常分支详表

本文件供 Agent 在执行各阶段时逐项核对使用，也是自检的依据。

## 一、各阶段核查清单

### 阶段 0 任务契约核查
- case_id 已提取并写入 audit_state.md。
- output_contract 字段清单已逐字段列出，写 result.json 时逐字段对照。
- 目标格式已确定或已触发降级策略。
- 材料文件全部实际读取，未凭文件名推断内容。
- PDF 已用平台 pdf-text-tool 提取，扫描件走 ocr-tool。

### 阶段 1 抽取穷尽性核查
- 逐章节扫描记录：每章是否已扫、是否含图表注、是否含附录。
- 正文引用点计数已记录（区分唯一标记数与引用点次数，如 [3] 出现两次记 2 个引用点）。
- 上标与非上标、方括号与著者-年份混用情况已记录。
- 文献条目计数已记录，null 字段如实标记。
- 抽取分块时块间边界处的句子未截断。

### 阶段 2 去重核查
- 每个合并决策四要素齐全：保留条目、被并条目、判据、风险等级。
- DOI 相同的合并直接执行；仅题名相似的合并列为待确认。
- 中英题名对应（如期刊双语言发表）按"同 DOI 或同卷期页"判据，否则待确认。
- 合并后旧键到新键映射表完整，后续引用点全部换成新键。

### 阶段 3 一致性核查
- 双向矩阵已构建：每个引用点都能映射到条目，或列入孤儿清单。
- 未引用条目已先核对图表注与附录再判定。
- 顺序编码制编号校验五项全过：连续性、首现顺序、一编号一含义、样式统一（上标一致）、交叉引用同步（图表注、附录）。
- 著者-出版年制校验：正文年份与条目年份一致、et al 用法符合目标规范。
- 挂靠位置审查完成：每个引用点标注"合理"或"位置可疑"及理由。

### 阶段 4 元数据核查
- 每条目三级分级（完整/可疑/缺失）已标注，可疑项写明可疑原因。
- DOI 校验只做了格式合法性（10. 开头、斜杠后非空）与材料内交叉核对；网络反查仅在工具可用时进行。
- 没有任何条目在无证据情况下被标为"已核实"。
- 需人工确认清单已汇总。

### 阶段 5 格式化核查
- 字段映射逐字段执行（对照 references/format-mapping.md）。
- DOI、卷期页、文献类型标识全部保留。
- 中文条目与英文条目标点按目标规范区分处理。
- 修订稿内引用标记与 references_final 序号一一对应。
- change_records 每条含：锚点、改动前、改动后、依据。

## 二、异常分支详表

| 编号 | 异常情形 | 处置 | 结果标注 |
|---|---|---|---|
| E1 | case.json 缺失或损坏 | 以 task.md 为契约来源；两者皆缺则停止并写失败说明 | status=failed，limits 写明原因 |
| E2 | 稿件文件缺失/无法解析（损坏 PDF、加密文件） | 尝试备用提取（ocr-tool）；仍失败则停止该产物 | status=failed，不编造稿件内容 |
| E3 | 文献库缺失，仅稿件内嵌列表 | 按内嵌列表执行全流程 | uncertainty 注明"无独立文献库可比对" |
| E4 | 文献库与稿件都无（纯写作任务无引用需求） | 检查任务说明是否确无引用要求；确认无引用则输出空矩阵说明 | status=complete，uncertainty 说明 |
| E5 | 正文引用标记无对应条目（孤儿引用） | 保留标记，列孤儿清单；若材料内有足够信息可补条目则补并标注"依据稿件补全" | manual_review_list 记录 |
| E6 | 条目从未被引用 | 列未引用清单，给删除或补引用两种建议，不擅自删除 | manual_review_list 记录 |
| E7 | 引用信息不全（只有编号无列表、作者缩写无法展开） | 不猜测对应；待匹配键入清单 | manual_review_list 记录 |
| E8 | 重复条目判据冲突（部分匹配部分矛盾） | 不合并，双条目保留并标风险 | dedup_records 记 risk=conflict |
| E9 | 目标格式不明 | 保持原稿格式做一致性修复 | limits 写明"目标格式未指定" |
| E10 | 编号冲突（同号不同条目、跳号） | 按首次出现顺序重排，冲突原文留痕 | numbering_issues 记录原始冲突 |
| E11 | 材料超预算（超长稿件、超大文献库） | 先完成抽取与校验，写 partial result.json，再增量补格式化产物 | status=partial，limits 列出未完成部分 |
| E12 | DOI 格式非法或字段自相矛盾 | 标可疑，不擅自修改元数据 | metadata_grades=suspicious，写原因 |
| E13 | 网络核验不可用或查询失败 | 一律标"未核实" | uncertainty 记录核验不可用 |
| E14 | 同名作者不同文献、同拼音中文作者 | 默认不合并 | manual_review_list 记录 |
| E15 | 图表注/附录中的引用 | 一并纳入矩阵与编号体系 | sources 锚点含图表注定位 |
| E16 | 引用标记为中文形式（如〔3〕、上标3） | 规范化为目标样式并在 change_records 留痕 | sources 保留原样式片段 |

## 三、终局自检清单（写 result.json 前执行）

1. result.json 语法合法，含 case_id 与 output_contract 全部字段。
2. status 与实际完成度一致。
3. 引用点总数、条目总数、孤儿数、未引用数、合并数之间能对账（总数 = 唯一标记数 + 孤儿标记数在逻辑上自洽）。
4. 每个"已核实"都有证据；每个可疑/缺失都在人工确认清单。
5. 每条 change_record 有锚点且锚点可在原稿定位。
6. /app/output 下四类产物齐全（或缺失的已写明原因）。
7. 无编造的文献条目、无编造的 DOI、无编造的核对结论。
